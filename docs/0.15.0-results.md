# 0.15.0 — measured, on the same deck twice

**Method.** A sixteen-slide Kubernetes training deck was authored from scratch
against `0.14.0`, taken to a deliverable state, and measured. The engine changes
in this branch were then implemented. The *same deck* — same content, same
palette, same type scale — was rebuilt using the new authoring primitives and
measured again with the same harness.

The two decks were checked for equivalence before either number was believed:
identical slide count, identical element count (434), and the words extracted
from both rendered PDFs are the same 1,803 tokens in the same multiset. v2 is
the same deck, built differently.

---

## What a review round costs

| | v1 (0.14.0) | v2 (0.15.0) | change |
|---|---:|---:|---:|
| `report.json` | 40,675 | 5,714 | **−86%** |
| `packet.json` | 14,778 | 10,748 | −27% |
| **One round, both read** | **55,453** | **16,462** | **−70%** |

The report's fall is grouping plus the removal of non-events plus compaction.
The packet's is almost entirely compaction — it was already defect-first from
0.13, and the fields that dominate it now (`slides[].text` at 5,091 tokens) are
untouched by this release. That is the next thing to look at, not a success to
claim here.

## What the findings say

| | v1 | v2 |
|---|---:|---:|
| occurrences reported | 357 | 162 |
| — info-level | 329 | 150 |
| — warnings | 28 | 12 |
| — errors | 0 | 0 |
| distinct codes | 7 | 6 |
| tokens spent on findings | 26,995 | 3,311 |
| **tokens per occurrence** | **75.6** | **20.4** |

The 195 occurrences that disappeared were checked one at a time, and every one
was a non-event:

| Removed | Count | Why it was not a finding |
|---|---:|---|
| `autofit-below-scale` | 145 | **All 145** had `declaredFontSize === effectiveFontSize`. Autofit shrank nothing. The check duplicated `font-below-scale` and described an event that had not happened. |
| `font-below-scale` on chrome and code | 34 | A slide number and a YAML block, both small on purpose. The 9pt legibility floor still applies to them. |
| `repeated-silhouette` | 16 | The absolute 0.93 cosine cut fired on 20 pairs whose similarity ran 0.98–1.00, because cosine over an all-positive vector cannot fall much below 1. |

Nothing an author could act on was removed: every surviving `(code, slide,
element)` triple is asserted to survive grouping, and `--issues flat` still
writes the old array.

## What the deck is worth

Unchanged, which is the point.

| | v1 | v2 |
|---|---|---|
| heuristics | 84 | 84 |
| hierarchy / contrast / density / variety / evidence / accessibility | 100 / 92 / 94 / 53 / 55 / 100 | identical |
| errors | 0 | 0 |
| round-trip | pass | pass |
| readiness | review | review |

Both stop at `review` for the same two reasons — variety 53 and evidence 55,
against a floor of 58. Those are design critiques of the deck, not of the
toolkit, and this release deliberately did not move them.

## What did not work

**Authoring cost fell 1%, against a projected 37%.**

| | v1 | v2 | change |
|---|---:|---:|---:|
| script total | 10,942 | 10,841 | −1% |
| — scaffolding | 2,108 | 1,975 | −6% |
| — mechanics | 4,291 | 4,311 | +0% |
| — content | 4,544 | 4,555 | +0% |

The roadmap projected that `flow` and `card` would remove most of the 12%
scaffolding and about a third of mechanics. On this deck they removed almost
nothing, and the reasons are worth writing down rather than explaining away:

- **Scaffolding fell 6%, not 93%.** Deleting the hand-written `card`, `bar`, and
  `stack` bodies saved 39 lines. But the deck still defines its palette, its type
  scale, its light/dark inverter, and six further composites — `chip`, `marker`,
  `node`, `boundary`, `heading`, `code` — that `flow` and `card` do not cover.
  The two primitives shipped were the two that recurred across decks; they were
  not most of what a deck writes.
- **Mechanics did not move at all.** Collapsing a `card(...)` plus `bar(...)`
  pair into one `card(..., { accent })` call moves the accent colour into an
  options object. It is one call instead of two and it cannot be got wrong, but
  it is the same number of tokens.

The projected saving depended on workstreams F (a `scaffold` command, snippets,
exemplar decks) and G (separating a `CONTENT` block from the layout functions),
neither of which was built. The honest reading is that `flow` and `card` are a
**correctness** change that happens to be small on tokens, and the authoring-cost
thesis is still unproven.

What they do buy is not nothing: `rounded-corner-overhang` — a check 0.14 needed
three new `ElementRecord` fields and an OOXML preset-geometry reader to
implement — cannot be expressed by a card drawn with `slide.card`. A primitive
that prevents a defect beats a check that finds it after a build, a render, and
a review round. That claim is asserted by running the real check over real
geometry, not by re-checking the arithmetic.

## Two bugs the exercise found

Both were found by using the tool rather than by reading it.

**A failed build left the previous build's verdict on disk.** A malformed native
chart threw deep inside the chart writer. The CLI reported it and exited 1,
which is correct. But `report.json` was still the last successful run's,
unchanged, still saying `"status": "pass"`, with nothing on it to say which
build it described. Build, then read the report, is what a model does, and it
got a green verdict for a build that never happened next to a `.pptx` that no
longer matched the script. Two wrong conclusions were drawn from those stale
files during this session before the mtimes gave it away. Fixed: a failed build
now replaces the report with one that records the failure.

**The budget gates were watching the wrong deck.** Every ceiling was set against
a healthy fixture, and the packet ceiling asserted the fixture stayed under
eight findings so a flood would not "pollute" the measurement. That is backwards
for a cost gate: a healthy deck can never exercise the field that turned out to
dominate. A 40,675-token report sat under a 4,000-token ceiling with CI green
throughout. A defective fixture now measures the expensive case, and the
invariant it pins is that cost tracks distinct findings rather than occurrences.

## Delivered

Four commits on `feat/0.15.0-evidence-signal`, `npm run verify` green at 681
tests across 70 files.

| Commit | Workstream |
|---|---|
| `feat(validation): report only what happened` | A — non-events |
| `feat(report): say each finding once, and stop indenting what a model reads` | B, C, H — grouping, compaction, gates |
| `feat(authoring): flow and card, the two primitives every deck rebuilt` | E — the kit |
| `fix(build): a failed build no longer leaves the last one's verdict on disk` | found by dogfooding |

One regression was introduced and caught by the suite: the review packet read
`report.issues` from disk and would have produced an empty packet against a
grouped report — indistinguishable from a healthy deck, which is the worst
possible way for it to fail.

## Not done

- **D** — `--check`, throwing at the call site, `suggestedEdit` on issues.
- **F** — `scaffold`, `snippet`, exemplar decks, and the guide shrink that
  follows them.
- **G** — delta packets (`review --since`), `kit extract`, `--only`, retiring
  the deprecated `quality` alias.
- **I** — the `chrome` role, per-slide review questions, issue provenance.

F and G are where the authoring-cost thesis stands or falls, and on this
evidence it should not be claimed until they are built and measured.
